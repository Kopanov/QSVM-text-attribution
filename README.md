# QSVM Text Attribution

Reader-facing code, data, and result artifacts for:

> Kalin Kopanov and Tatiana Atanasova, “A Systematic Benchmark of Quantum Support Vector Machines for Interpretable Attribution of AI-Generated Text” (2026).

The study benchmarks quantum support vector machines (QSVMs) against classical SVM controls for binary attribution of texts generated by Gemma 3 and Qwen 2.5. It uses a paired-prompt corpus of 5,800 generated texts, 83 Stage 1 configurations, 12 Stage 2 configurations, and an independent 1,000-text test corpus.

## Main findings

- The best large-scale QSVM validation accuracy is approximately 88%.
- A recipe-matched classical RBF SVM reaches 97.76% at 14 dimensions.
- At 14 dimensions, the mean off-diagonal quantum-kernel entry is about 400 times smaller than its classical RBF counterpart, consistent with kernel concentration.
- The independent test corpus preserves the large-scale model ranking.
- The released PCA salience values describe the fitted representation; they are not explanations of the trained QSVM classifier.

## Repository contents

- `source/` — analytical training and evaluation source code.
- `data/` — the 2,900 main prompt records, 5,800 generated main-corpus texts, 500 independent-test prompts, 1,000 independent-test texts, and generation protocol.
- `results/stage1/` — one compact JSON per Stage 1 configuration plus a CSV index.
- `results/stage2/` — one compact JSON per Stage 2 configuration plus a CSV index.
- `results/feature_salience/` — compact PCA representation-salience artifacts used for Table 7 and Figure 4, including the full-data dimension-16 sensitivity result.
- `results/experiment_2_5.json` — recipe-matched classical controls from Table 11.
- `results/independent_test/` — Section 3.4 and Table 12.
- `results/kernel_concentration/` — Section 4.2, Figure 7, and the associated numerical diagnostics.
- `environment/` — the published and replication software stacks.

See the README files inside `data/`, `results/`, and `source/` for format and provenance notes.

## Quick inspection

The concise CSV indexes are the easiest entry points:

```bash
python - <<'PY'
import pandas as pd

stage1 = pd.read_csv("results/stage1/summary.csv")
print(stage1.sort_values("quantum_accuracy", ascending=False).head(10))

stage2 = pd.read_csv("results/stage2/summary.csv")
print(stage2[["configuration", "feature_mode", "quantum_accuracy", "classical_accuracy"]])
PY
```

## Small local demonstration

The published large experiments used substantial CPU time. A small exact-statevector run can be launched from the repository root:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

TRAINING_SAMPLES=200 \
VALIDATION_SAMPLES=50 \
QUANTUM_FEATURE_DIM=4 \
QUANTUM_BACKEND=qiskit_statevector_deterministic \
STATEVECTOR_SHOTS=None \
MONITOR_RESOURCES=false \
python source/qsvm_cli.py
```

The default input is `data/main_corpus.csv`; set `DATA_FILE` to override it.

## Artifact policy

This release keeps the numerical results, experimental parameters, preprocessing settings, and software versions needed to interpret the paper. It intentionally omits duplicate result files, kernel matrices, fitted model objects, cache files, resource-monitoring time series, scheduler scripts, hostnames, local filesystem paths, and SLURM job identifiers.

Each Stage 1 and Stage 2 run JSON is a sanitized compact copy of the original run overview. Numerical metrics were not changed. The `git_hash` value `47c928b` records the private development snapshot used by the original runs; it is provenance metadata and is not a commit in this clean public history.

Some generated texts contain fictional names, organizations, or email-like strings because they are model outputs. They are not repository credentials or author contact records.
